
# Roomly — система бронирования переговорных

**Автор:** Жантлеуов Мадияр  
**Версия:** 1.0  
**Технологии:** HTML, CSS, JavaScript, LocalStorage

## Цель проекта

Разработать веб-приложение для бронирования переговорных комнат,
проверки занятости помещений и отмены бронирований.

## Проблема и актуальность

При ручном планировании встреч сотрудники могут случайно
забронировать одну комнату на одинаковое время.
Roomly проверяет пересечения и показывает список встреч.

## Целевая аудитория

- Сотрудники офиса.
- Администраторы помещений.
- Руководители команд.

## Аналоги

1. Microsoft Outlook Room Finder:
   https://support.microsoft.com/en-gb/outlook/use-the-scheduling-assistant-and-room-finder-for-meetings

2. Skedda:
   https://www.skedda.com/platform/meeting-room-booking-system

3. Robin:
   https://robinpowered.com/platform/room-scheduling

В отличие от корпоративных решений, Roomly является
учебным проектом с локальным хранением данных.

## Функциональные возможности

1. Просмотр переговорных комнат.
2. Создание бронирования.
3. Проверка даты и времени.
4. Запрет пересечения бронирований одной комнаты.
5. Отмена существующего бронирования.
6. Отображение списка бронирований.
7. Подсчёт комнат, свободных в текущий момент.
8. Сохранение записей в LocalStorage.
9. Адаптивный интерфейс.

## Функциональные требования

- FR-1: показывать список переговорных.
- FR-2: создавать бронирования.
- FR-3: проверять корректность даты и времени.
- FR-4: предотвращать пересечения интервалов.
- FR-5: отменять бронирования.
- FR-6: отображать список занятости.
- FR-7: сохранять записи в браузере.

## Нефункциональные требования

- NFR-1: интерфейс должен работать в современном браузере.
- NFR-2: интерфейс должен адаптироваться к экрану.
- NFR-3: ошибки ввода должны сопровождаться сообщениями.
- NFR-4: данные должны сохраняться между перезагрузками.

## Пользовательские сценарии

1. Сотрудник выбирает комнату, дату и время, затем создаёт бронь.
2. Сотрудник просматривает расписание и занятость.
3. Сотрудник отменяет ненужное бронирование.

## Ограничения

- Одно помещение не может иметь пересекающиеся брони.
- Время окончания должно быть позже начала.
- Прошедшие даты не принимаются.
- Данные хранятся локально в браузере.
- Синхронизация между пользователями отсутствует.
- Авторизация и серверная база данных не реализованы.

## Архитектура

- `index.html` — структура страницы.
- `style.css` — оформление интерфейса.
- `app.js` — логика бронирования и проверки.
- `docs/analysis.md` — анализ предметной области.

## Запуск

Открой `index.html` в браузере.

Для разработки рекомендуется расширение Live Server
в Visual Studio Code.

## Тестирование

Проверить:
- создание корректной брони;
- отмену бронирования;
- запрет пересечения времени;
- пустое имя;
- неправильную дату;
- окончание раньше начала;
- одновременные встречи в разных комнатах;
- сохранение данных после перезагрузки.

Результаты тестов необходимо зафиксировать после
фактической проверки приложения.

## Перспективы развития
